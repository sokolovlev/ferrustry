# Тестирование

Перед каждым коммитом — `scripts/check.sh` (fmt, check, clippy `-D warnings`, тесты, release-сборка).
Запускайте его **отдельной командой** и смотрите код возврата: не через `| tail`, иначе ошибка
теряется (так в репозиторий попал коммит 18442a2 с упавшим clippy).

## Что проверяют тесты

| Где | Что | Приём |
|---|---|---|
| `ferrustry-sim/tests/sim.rs` | Ленты, буры, плавильня, энергия, сохранения | Сохранение ресурсов (`assert_conserved`), `World::validate`, случайные стройки (`RandomBuilder`) с проверкой инвариантов и воспроизводимости |
| `ferrustry-sim/tests/stage3.rs` | Экономика, разветвитель, сортировщик, мост, батареи | Регрессия: тест на устаревшие связи после сноса падает без исправления |
| `ferrustry-sim/tests/thermal.rs` | Жидкости и тепло | Точное число циклов при перегреве (9 против 50) |
| `ferrustry-sim/tests/combat.rs` | Поле путей, турели, волны, поражение | Детерминизм боя и продолжение после save/load |
| `ferrustry-sim/tests/content.rs` | Топливо, склад, дуговая турель, броня, дальнобойные враги, перебор урона | Точный урон по тикам; смешанный бой через save/load; ровно 4 выстрела пяти турелей по ползуну; учёт урона в полёте сходится каждый тик боя |
| `ferrustry-sim/src/*` (модульные) | Сегменты, ГСЧ, генератор карт, схемы, поле путей | Гарантии генератора на 36 картах; 4 поворота схемы = исходная; починка поля путей ≡ полная перестройка на случайной стройке |
| `ferrustry-format` | Сохранения, replay, схемы | Round-trip и продолжение с тем же хешем; повреждённый и обрезанный файл; другой контент; чужая версия или вид файла; поиск подменённой команды в replay; схемы с переназначением имён |
| `ferrustry-content` | Валидация контента, справочник | Справочник и руководства не отстают от данных; английская документация зеркалит русскую (см. ниже) |
| `ferrustry-render/tests/offscreen.rs` | Рендер кадра на GPU | Пиксели цветов бренда, эмблема ядра, свечение разряда; без GPU — `SKIPPED` |
| `ferrustry-client` (модульные) | Логика интерфейса без окна | Клики по меню и панели, стройка, копирование и вставка |

### Дифференциальные тесты

Усыпление лент и буров — оптимизация, которая не должна менять результат. Тесты строят два мира:
обычный и с `set_sleep_enabled(false)`, гоняют одинаково и сравнивают `state_hash` по ходу. Любая
новая логика пробуждения должна проходить их.

### Документация под тестами

- Справочники контента генерируются из `base.ron`; тест `reference_doc_is_up_to_date` падает,
  если устарел русский или английский файл. Обновить: `FERRUSTRY_BLESS=1 cargo test -p ferrustry-content reference`.
- `guides_cover_all_content`: каждый враг описан в руководстве игрока, каждый вид постройки — в
  описании формата контента, на обоих языках.
- `english_docs_mirror_russian`: у каждого русского документа есть английский с тем же числом
  разделов, и наоборот.

## Сквозные проверки (в CI на Linux)

| Проверка | Команда |
|---|---|
| Сохранение → загрузка → тот же хеш | `cargo run --release -p ferrustry-headless -- save-check` |
| Replay на другой ОС | `record` на Linux, `replay` на Windows и macOS (ARM) — хеши совпадают |
| Скриншот клиента | `ferrustry --screenshot client.png --ticks 600 --zoom 40 --center 96,61` |
| Окно поднимается | `xvfb-run ... ferrustry --frames 120` |
| Интерфейс мышью | `scripts/e2e-ui.sh target/release/ferrustry out/` — Xvfb + xdotool |

`scripts/e2e-ui.sh` кликает по экранным координатам окна 1280×720. Если меняется раскладка меню,
экрана новой игры или число слотов во вкладке LOGISTICS, координаты в скрипте нужно обновить
(комментарии рядом объясняют расчёт).

## Производительность

- Время: `ferrustry-headless bench <b1|b2|b2-blocked|b2-comb|b3|b5|b8>` (`--full-flow` — эталон без
  починки поля путей; хеш состояния обязан совпасть), полный набор с медианами —
  `scripts/bench-suite.sh` (Windows: `scripts/bench-suite.ps1`). На VM время шумит на ±10%.
- **Инструкции на тик** — стабильная метрика для сравнения версий на одной машине:

  ```bash
  for t in 300 600; do
    valgrind --tool=callgrind --callgrind-out-file=cg.$t \
      target/release/ferrustry-headless bench b3 --conveyors 100000 --warmup 0 --ticks $t >/dev/null
  done
  # (итог cg.600 − итог cg.300) / 300 = инструкций на тик без затрат на построение
  ```

  Сравнивайте с предыдущим коммитом, собранным в отдельном worktree. Результаты — в
  [docs/performance.md](../performance.md).
- Аллокации на тик и пиковая память — в выводе `bench` (`allocations_per_tick`, `peak_rss_kib`).
- Многопоточность: `--example parallel_ceiling` (потолок ускорения при владении данными) и
  `--example fork_join_cost` (цена вызова пула потоков) в `ferrustry-headless`.
- Рефакторинг раскладки данных: `--example behaviour_fingerprint` печатает отпечаток наблюдаемого
  поведения B3 (через публичный API, не зависит от формата сохранений). Соберите его на старой и
  новой версии — вывод обязан совпасть.
