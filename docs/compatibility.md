# Совместимость

Ferrustry — оригинальная игра, поэтому совместимость означает **совместимость Ferrustry с самим
собой** между версиями и платформами. Совместимость с форматами, серверами и модами других игр
**не является целью**.

## 1. Матрица форматов

| Формат | Назначение | Статус | Политика версий |
|---|---|---|---|
| Карта (`.fmap`) | Террейн, руда, стартовые постройки, правила | Не реализовано | Чтение всех старших версий формата ≥ 1.0 |
| Сохранение (`.fsave`) | Полное состояние симуляции | **Частично** (формат 4.0 с 2026-11-17 — новый контент: склады, топливо, дуговые турели, вражеские снаряды; файлы 3.x и старше отклоняются с ошибкой версии — до релиза миграции не делаем): контейнер v1.0, round-trip и продолжение с тем же хешем протестированы; переназначение ID контента и миграции не реализованы (файл с другим контентом отклоняется) | Чтение сохранений предыдущей minor-версии игры; миграции |
| Схема (`.fschem`, + текстовая строка base64) | Фрагмент постройки для копирования | **Реализовано** (без текстовой строки): постройки по **именам** контента, проверка границ | Обратная совместимость всегда; неизвестная постройка — понятная ошибка |
| Контент (RON) | Ресурсы, блоки, юниты, рецепты | **Частично**: ресурсы, полы, руды, 6 видов построек; юнитов нет | Схема версионируется, валидатор |
| Сетевой протокол | Клиент ↔ сервер | Не реализовано | Строгое совпадение `protocol_version` |
| Replay (`.freplay`) | Начальный мир + поток команд + контрольные хеши | **Реализовано**: контейнер v1.0, секции NAMES/META/WORLD/INPUTS/CHECKPOINTS | Только та же версия симуляции (`SIM_VERSION`) и тот же контент |

## 2. Контейнерный формат (черновик)

```text
magic      : 8 байт  "FERRUSTR"
kind       : u8      (map / save / schematic / replay)
version    : u16 major, u16 minor
flags      : u32     (сжатие и т. п.)
sections   : [ { id: u32, len: u64, crc32: u32, data } ]   # данные секций сжаты zstd
```

- Реализованные секции: `1` — таблица имён контента, `2` — состояние мира (postcard).
  Файл проверяется на CRC32 каждой секции, лимит распаковки 512 МиБ и структурную целостность мира.
- Ограничение v1.0: секция мира — прямая сериализация структур симуляции; при изменении их
  раскладки потребуется bump версии и миграция.
- Неизвестные секции пропускаются (forward-compat для minor-версий).
- Контент сохраняется **по строковым именам** с таблицей «имя → ID» в файле, чтобы изменение
  порядка контента не ломало сохранения.
- Каждый формат получает набор эталонных файлов в `tests/fixtures/` и тесты «загрузить → сохранить →
  сравнить» и «старая версия → загрузка».

## 3. Матрица платформ

| Платформа | Цель | Статус |
|---|---|---|
| Linux x86_64 | Клиент + сервер | Headless: CI зелёный |
| Windows x86_64 | Клиент + сервер | Headless: CI зелёный; эталонная машина владельца |
| macOS (Apple Silicon, x86_64) | Клиент + сервер | Headless: CI зелёный (ARM64) |
| Android | Клиент (позже) | Не начато |

## 4. Детерминизм

| Свойство | Цель |
|---|---|
| Тот же бинарник, та же платформа | Побитово одинаковый хеш состояния — **проверяется тестами** |
| Разные платформы | **Проверяется в CI**: replay, записанный на Linux x86_64, воспроизводится на Windows x86_64 и macOS ARM64 |
| Разные версии игры | Не гарантируется |

Мультиплеер не опирается на кроссплатформенный детерминизм (авторитарный сервер), но он
нужен для replay и регрессионных тестов.
