# Совместимость

Ferrustry — оригинальная игра, поэтому совместимость означает **совместимость Ferrustry с самим
собой** между версиями и платформами. Совместимость с форматами, серверами и модами других игр
**не является целью**.

## 1. Матрица форматов

| Формат | Назначение | Статус | Политика версий |
|---|---|---|---|
| Карта (`.fmap`) | Террейн, руда, стартовые постройки, точки появления, правила, стартовый запас | **Реализовано** (2026-11-20, формат 1.0): контент по **именам** (только использованные), своя версия, не зависящая от сохранений, проверки размеров, индексов и точек появления; редактор карт в клиенте, `map-gen`/`map-check` в headless | Чтение всех старших версий формата ≥ 1.0 |
| Сохранение (`.fsave`) | Полное состояние симуляции | **Частично** (формат 8.0 с 2026-11-20 — локальная перестройка энергосетей, свободные номера сетей; файлы 7.x и старше отклоняются с ошибкой версии — до релиза миграции не делаем): контейнер v1.0, round-trip и продолжение с тем же хешем протестированы; переназначение ID контента и миграции не реализованы (файл с другим контентом отклоняется) | Чтение сохранений предыдущей minor-версии игры; миграции |
| Схема (`.fschem`, + текстовая строка base64) | Фрагмент постройки для копирования | **Реализовано** (без текстовой строки): постройки по **именам** контента, проверка границ; с 2026-11-20 своя версия формата 1.0 (файлы, записанные раньше с версией сохранений 2.x–7.x, читаются) | Обратная совместимость всегда; неизвестная постройка — понятная ошибка |
| Контент (RON) | Ресурсы, блоки, юниты, рецепты | **Реализовано**: предметы, жидкости, полы, руды, 21 вид построек, враги и состав волн ([формат](content-format.md)) | Схема версионируется, валидатор |
| Сетевой протокол | Клиент ↔ сервер | Не реализовано | Строгое совпадение `protocol_version` |
| Replay (`.freplay`) | Начальный мир + поток команд + контрольные хеши | **Реализовано**: контейнер v1.0, секции NAMES/META/WORLD/INPUTS/CHECKPOINTS | Только та же версия симуляции (`SIM_VERSION`) и тот же контент |

## 2. Контейнерный формат (черновик)

```text
magic      : 8 байт  "FERRUSTR"
kind       : u8      (map / save / schematic / replay)
version    : u16 major, u16 minor
flags      : u32     (сжатие и т. п.)
sections   : [ { id: u32, len: u64, crc32: u32, data } ]   # данные секций сжаты zstd
```

- Версия в заголовке — своя у каждого вида файла: сохранения и повторы — версия сохранений (8.0), карты и
  схемы — своя (1.0), потому что хранят контент по именам и не зависят от структур симуляции.
- Реализованные секции: `1` — таблица имён контента, `2` — состояние мира (postcard).
  Файл проверяется на CRC32 каждой секции, лимит распаковки 512 МиБ и структурную целостность мира.
- Ограничение v1.0: секция мира — прямая сериализация структур симуляции; при изменении их
  раскладки потребуется bump версии и миграция.
- Неизвестные секции пропускаются (forward-compat для minor-версий).
- Контент сохраняется **по строковым именам** с таблицей «имя → ID» в файле, чтобы изменение
  порядка контента не ломало сохранения.
- Каждый формат получает набор эталонных файлов в `tests/fixtures/` и тесты «загрузить → сохранить →
  сравнить» и «старая версия → загрузка».

## 3. Матрица платформ

| Платформа | Цель | Статус |
|---|---|---|
| Linux x86_64 | Клиент + сервер | CI зелёный: headless, рендер вне экрана (lavapipe), окно и интерфейс мышью (Xvfb) |
| Windows x86_64 | Клиент + сервер | CI зелёный (сборка, тесты, replay с Linux); клиент проверен владельцем на Windows 10; эталонная машина |
| macOS (Apple Silicon, x86_64) | Клиент + сервер | CI зелёный на ARM64 (сборка, тесты, replay с Linux); окно клиента не проверялось |
| Android | Клиент (позже) | Не начато |

## 4. Детерминизм

| Свойство | Цель |
|---|---|
| Тот же бинарник, та же платформа | Побитово одинаковый хеш состояния — **проверяется тестами** |
| Разные платформы | **Проверяется в CI**: replay, записанный на Linux x86_64, воспроизводится на Windows x86_64 и macOS ARM64 |
| Разные версии игры | Не гарантируется |

Мультиплеер не опирается на кроссплатформенный детерминизм (авторитарный сервер), но он
нужен для replay и регрессионных тестов.
